## 1. Название продукта

**«Задачник»** — минималистичный трекер личных задач: заголовок, срок, статус, заметка. Ничего лишнего, главное — чтоб работал.

## 2. Цель проекта и целевая аудитория

**Цель:** дать человеку простой инструмент ведения списка задач с понятными статусами и сроками — без проектов, приоритетов, аккаунтов и украшательств. Открыл → посмотрел, что висит → сделал → отметил.

**Целевая аудитория:** частное лицо, которому нужен честный рабочий список дел (учёба, подработки, бытовые задачи) с минимальной структурой: что, к какому числу, в каком состоянии.

*Домыслы:* пользователь заходит 1–5 раз в день короткими сессиями; задач в списке — 5–30; самое частое действие — перевести задачу в следующий статус; дата нужна, чтобы не пропустить срок (поэтому просрочка должна быть заметной, а ближайший срок — на виду).

## 3. Что упразднено из заказа

- **Нативная разработка (Swift, Xcode).** Заказ исполняется как веб-приложение: рамки учебного кейса — веб-трекер.
- **UserDefaults → localStorage.** Дух требования сохранён: данные только на устройстве, без сервера.
- **Today-extension (виджет iOS) → веб-аналог:** блок «Ближайшая по сроку невыполненная задача» над списком с переходом к карточке (раздел 6.3).
- **Шаринг текста извне (share-extension) → веб-аналог:** быстрое добавление задачи вставкой текста (раздел 6.4).
- «Лучше без дополнительных библиотек» → **ванильный JS, ноль фреймворков и внешних зависимостей** на клиенте; шрифт системный (приложение полностью работает офлайн).

## 4. Вопросы «клиенту» (гипотетические, с принятыми ответами)

1. **Обязательна ли дата у задачи?**
   → Да, у каждой задачи есть срок; при добавлении по умолчанию — сегодня. Дата нужна для блока «ближайшая задача» (аналог today-extension) и для пометки просрочки.
2. **Можно ли менять статус, не открывая редактирование?**
   → Да, статус переключается прямо на карточке — это самое частое действие, его нельзя прятать в модалку.
3. **Что делать с просроченными задачами?**
   → Ничего автоматически: невыполненная задача с прошедшей датой получает бейдж «просрочена». Переносить или удалять — решает пользователь (минимализм, никаких сюрпризов с данными).
4. **Как должна работать вставка текста?**
   → Первая непустая строка вставленного текста становится заголовком, остальное — заметкой; срок — «сегодня», статус — «новая». Даты в тексте не распознаём — деталь правится потом (предсказуемое поведение важнее «магии»).
5. **Нужны ли аккаунты и синхронизация?**
   → Нет. Личный трекер: данные хранятся в localStorage устройства, никакого входа.

## 5. Роли пользователей и права

**Ролей нет — личное использование.** Один пользователь устройства без авторизации; полный доступ ко всем функциям.

## 6. Экраны и функции

### 6.1. Главный экран

**Назначение:** единственный рабочий экран — список задач со всеми действиями.

**Элементы (сверху вниз):**
- **Шапка:** логотип, название «Задачник», строка-счётчик «Всего N · новых M · в процессе K · выполнено L».
- **Блок «Ближайшая задача»** (см. 6.3) — плашка над списком.
- **Форма добавления:** поле «Заголовок задачи» (обязательное), поле «Срок» (type=date, по умолчанию сегодня), кнопка «Добавить». Создаёт задачу со статусом «новая» и пустой заметкой (детали — потом в редактировании).
- **Панель «Вставить текст»** (свёрнута, по клику раскрывается): textarea + кнопка «Создать задачу из текста»; правила парсинга — 6.4.
- **Фильтр по статусу:** сегмент-переключатель «Все (N) / Новые (M) / В процессе (K) / Выполненные (L)» — клик мгновенно фильтрует список; счётчики считаются по всему списку, не по фильтру.
- **Список задач** — карточки; сортировка: по дате по возрастанию (ближайшие сверху), выполненные — в самом низу.
- **Карточка задачи:** цветной бейдж статуса (новая — серый, в процессе — синий, выполнено — зелёный); заголовок; бейдж даты («сегодня», «завтра», «5 ноября»; для просрочки — красный бейдж «просрочена · 3 ноября»); заметка, если есть (до 2 строк); компактный **выбор статуса** (select) прямо в карточке; кнопки «Редактировать» и «Удалить» (двухшаговое подтверждение: по первому клику кнопка меняется на «Точно удалить?» на 3 секунды).
- **Пустые состояния:** список пуст — «Задач нет. Добавьте первую или вставьте текст.»; фильтр не дал результатов — «В этом статусе задач нет».

**Действия:** добавить (форма или вставка); выбрать фильтр; сменить статус на карточке; редактировать (модалка 6.2); удалить (с подтверждением); перейти к ближайшей задаче (6.3).

### 6.2. Модальное окно «Редактирование задачи»

**Назначение:** полный набор полей задачи.

**Элементы:** «Заголовок» (обязательное), «Срок» (date, обязательное), «Статус» (select: новая / в процессе / выполнено), «Заметка» (textarea, опционально). Кнопки «Сохранить» и «Отмена». Открытие — по «Редактировать» на карточке.

### 6.3. Блок «Ближайшая задача» (аналог today-extension)

**Правила:**
- Показывает **невыполненную** задачу (статус ≠ «выполнено») с **ближайшей датой**; при равных датах — созданная раньше.
- Содержимое: подпись «Ближайшая по сроку невыполненная задача», заголовок, бейдж даты (если дата прошла — красный «просрочена»), бейдж статуса.
- Клик по плашке → плавная прокрутка к карточке задачи + краткая подсветка карточки (~1,5 с).
- Если невыполненных задач нет — блок скрыт (счётчик в шапке и так покажет нули).

### 6.4. Быстрое добавление вставкой текста (аналог share-extension)

**Правила парсинга вставленного текста:**
- обрезка пробелов по краям; первая непустая строка → **заголовок** (обрезается до 120 символов);
- всё, что после первой строки, → **заметка** (пустые строки в начале отбрасываются);
- нет ни одной непустой строки → кнопка неактивна, подсказка «Вставьте текст задачи»;
- созданная задача: срок — «сегодня», статус — «новая»; после создания панель сворачивается, задача видна в списке.

## 7. Данные

**Хранение:** `localStorage`, сервер данных не хранит (только раздаёт статику). При недоступности localStorage (приватный режим) — работа в памяти: данные живут до перезагрузки страницы.

- Ключ: `zadachnik.tasks.v1` — JSON-массив задач. **Единственный ключ**: демо-данные создаются, только если ключ отсутствует; удаление всех задач (пустой массив) демо-данные не возвращает.

**Структура задачи:**

```json
{
  "id": "t-1730700000000-x7k2p",
  "title": "Отправить отчёт по проекту",
  "date": "2026-11-03",
  "status": "in_progress",    // "new" | "in_progress" | "done"
  "note": "Разделы 1–3 готовы, осталось приложение",
  "createdAt": 1730700000000,
  "updatedAt": 1730700000000
}
```

**Демо-данные:** при первом запуске (ключ отсутствует) создаются **7 живых задач** — все три статуса и осмысленные даты: просроченная невыполненная («Отправить отчёт по проекту», вчера), задачи на сегодня и завтра, задача на +3 дня в процессе, 2 выполненные (сегодня и вчера). Первый запуск не пустой и сразу демонстрирует фильтры, блок «ближайшая задача» и маркер просрочки.

## 8. Мини-брендбук

- **Название:** «Задачник».
- **Характер стиля:** утилитарный, сдержанный, «инженерный» — без декора, красиво = аккуратно и читаемо.
- **Палитра (холодная, стальная — заметно отличается от тёплого Tracker_1 и делового Tracker_3):**
  - `#3D5A80` — основной акцент (стальной синий): кнопки, активный фильтр, статус «в процессе»
  - `#2E4057` — тёмный акцент: hover-состояния
  - `#F5F6F8` — фон страницы (холодный светло-серый)
  - `#FFFFFF` — карточки
  - `#1F2933` — основной текст (графит)
  - `#64707D` — вторичный текст, счётчики
  - `#64707D` — статус «новая» (нейтральный серый бейдж)
  - `#4A7C59` — статус «выполнено» (приглушённый зелёный)
  - `#A6463D` — просрочка, удаление (кирпичный, не «тревожный»)
  - `#D9DDE3` — границы и разделители
- **Шрифт:** системный стек `system-ui, "Segoe UI", Roboto, "Helvetica Neue", Arial, sans-serif` — ноль внешних загрузок, в духе «без дополнительных библиотек»; работает офлайн.
- **Логотип:** скруглённый квадрат стального синего цвета с белой галочкой (`info\logo.svg`); в шапке и как favicon.
- **Фактура:** лёгкое скругление (6 px), тонкие границы 1 px вместо теней, плотная аккуратная типографика.

## 9. Требования к адаптивности

- **Desktop (≥ 1024 px):** контентная колонка по центру (макс. ~720 px) — трекер остаётся однопанельным списком.
- **Tablet (768–1023 px):** то же, чуть плотнее.
- **Mobile (360–431 px):** одна колонка; форма добавления и фильтр перестраиваются в вертикальный поток; сегмент-фильтр при необходимости переносится на 2 строки; сенсорные цели ≥ 44 px.
- Отсутствие горизонтального скролла на всех контрольных ширинах (360 / 768 / 1024 / 1440).

## 10. Критерии готовности MVP (проверяемые)

1. Приложение открывается по адресу `http://localhost:3002` после одной команды запуска.
2. При первом запуске видны 7 демо-задач со всеми тремя статусами (первый запуск не пустой).
3. Задачу можно добавить с главного экрана за одно действие (заголовок + срок, Enter или кнопка).
4. Полный CRUD: просмотр списка, добавление, редактирование всех полей через модалку, удаление с двухшаговым подтверждением.
5. Фильтр по статусу «Все / Новые / В процессе / Выполненные» работает мгновенно, со счётчиками.
6. Статус меняется с карточки (select) и в модалке редактирования.
7. Блок «Ближайшая по сроку невыполненная задача» показывает задачу с ближайшей датой; клик прокручивает к её карточке и подсвечивает.
8. Вставка текста создаёт задачу: первая строка → заголовок, остальное → заметка, срок «сегодня».
9. Невыполненная задача с прошедшей датой помечена красным бейджем «просрочена».
10. Сортировка списка: по дате по возрастанию, выполненные — внизу.
11. Данные переживают перезагрузку страницы (localStorage); при недоступности localStorage приложение работает в памяти без ошибок.
12. Клиент — ванильный JS: ноль фреймворков, библиотек и внешних загрузок; в HTML/CSS/JS — подробные комментарии на русском (каждый блок/функция — что это и что делает).
13. Интерфейс на русском; вёрстка корректна на 360 px и на desktop; без гориз. скролла.

## 11. Вне скоупа

- Нативные приложения (Swift/Xcode), виджеты iOS (today-extension как виджет), интеграция системного шаринга.
- Аккаунты, вход, синхронизация между устройствами.
- Приоритеты, метки, подзадачи, проекты, исполнители.
- Поиск и сортировки на выбор пользователя (фиксированная сортировка из п. 10).
- Напоминания, пуш-уведомления, календарь.
- Импорт/экспорт данных, архив, корзина.
- Тёмная тема, PWA/service worker, оффлайн-режим как фича.
